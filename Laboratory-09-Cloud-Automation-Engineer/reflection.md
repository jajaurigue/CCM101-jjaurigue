# Mission Reflection

Completing this cloud automation mission helped me understand why automation is important in managing cloud infrastructure. When administrators manage hundreds of servers, performing tasks manually takes a lot of time and increases the chance of human error. Automation allows repetitive tasks, such as backups, to run consistently and helps ensure that important data is protected without depending entirely on someone remembering to do the work.

However, automation also has risks. A small mistake in a script can cause serious problems, especially when the same script runs across hundreds or thousands of servers. A destructive command or incorrect file path could delete important data or affect many systems. This taught me that scripts should be reviewed, tested in a safe environment, and monitored before being used in production.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash uses commands, variables, and sequential instructions to perform tasks directly in the Linux environment. Docker Compose uses YAML to describe and manage application services and their configurations. Both are useful for automation, but they solve different problems.

From Laboratory 1 to Laboratory 9, my understanding of Cloud Computing has developed from learning basic cloud concepts to working with infrastructure, containers, data services, deployment, operations, security, and automation. These activities helped me see that cloud computing requires not only deploying applications but also maintaining, protecting, and managing them efficiently.

The role I enjoyed most was Cloud Security Engineer because I learned how firewall rules can help protect a server and control access to network services. This mission also showed me how security and automation can work together to improve reliability. Overall, I learned that cloud engineers must continue practicing, testing their work, documenting procedures, and thinking carefully before applying changes to real systems.
