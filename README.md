# Laboratory Activity 2: Build the Cloud Infrastructure Blueprint

## Mission Overview
This activity simulates the planning phase of cloud deployment. I investigated a Linux cloud environment, identified core infrastructure components, compared major cloud providers, and designed a simple cloud architecture blueprint.

## Objectives
- Explain the major components of cloud infrastructure
- Investigate hardware and software resources in a Linux environment
- Differentiate compute, storage, networking, and identity resources
- Compare services across AWS, Azure, and Google Cloud
- Create technical documentation and architecture diagram

## Cloud Infrastructure Components
- *Compute:* Processing power to run applications and execute tasks
- *Storage:* Persistent data saving and retrieval
- *Networking:* Connectivity between resources, users, and the internet
- *Operating System:* Foundation that manages all hardware and software

## Tools Used
- KillerCoda Playground (Ubuntu 24.04.4 LTS)
- GitHub (version control & portfolio)
- Hand-drawn Diagram / Paper
- Linux Terminal / Command Line

## Linux Commands Executed
- cat /etc/os-release → Check Operating System details
- uname -r → Check Kernel Version
- cat /proc/cpuinfo → Check CPU model and specs
- nproc → Count CPU Cores
- free -h → Check Memory/RAM
- df -h → Check Disk Capacity
- hostname → View system hostname
- hostname -I → View IP Address

## Skills Learned
- How to inspect system resources using Linux commands
- Understanding the four pillars of cloud infrastructure
- Comparing equivalent services across different cloud providers
- Writing structured technical documentation with Markdown
- Designing basic cloud architecture diagrams

## Challenges Encountered
- Remembering the correct Linux commands and their output formats
- Understanding how each infrastructure component relies on the others
- Aligning and comparing services that have different names but same purpose
- Organizing documentation clearly and professionally
